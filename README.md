# BANKAI - نظام تقييم المندوبين (Flask)

## التشغيل محليًا
```bash
pip install -r requirements.txt
python3 app.py
```
هيفتح على http://localhost:5000 وهيعمل ملف `bankai.db` (SQLite) تلقائيًا أول مرة.

## النشر على Railway
1. اعمل push للمشروع ده على GitHub repo.
2. من Railway: New Project → Deploy from GitHub → اختار الـ repo.
3. Railway هيلاقي `Procfile` ويشغّل `gunicorn app:app` تلقائيًا.
4. **مهم**: لازم تضيف قاعدة بيانات حقيقية (Postgres) من Railway (Add Plugin → PostgreSQL) بدل SQLite، عشان SQLite بيتمسح مع كل deploy جديد على Railway (الـ filesystem مؤقت). بمجرد ما تضيف Postgres، Railway بيحط متغير `DATABASE_URL` تلقائيًا والكود بيقراه لوحده (`app.py`).

## هيكل المشروع
```
app.py          # الـ routes + الـ API
models.py       # جداول قاعدة البيانات (Evaluation, ShiftSession)
data.py         # بيانات المشرفين/الفروع/شيفتات المشرفين + بيانات مندوبين QCD2 + منطق التقاطع
templates/index.html
static/style.css
static/app.js   # كل منطق الفرونت إند (fetch من الـ API)
```

## إزاي تضيف بيانات QCD 1
افتح `data.py` واملأ `REPS_QCD1` بنفس شكل `REPS_QCD2`:
```python
REPS_QCD1 = [
    {"name": "اسم المندوب", "type": "full", "start": 9},   # full = 11 ساعة
    {"name": "اسم تاني", "type": "part", "start": 15},      # part = 5 ساعات
    ...
]
```

## إزاي تضيف/تعدل مشرفين أو شيفتات
- المشرفين: `BRANCHES` في `data.py`.
- شيفتات المشرفين (2ص-10ص إلخ): `SUPERVISOR_SHIFTS` في `data.py`.
- مدة الشيفت لكل نوع دوام: `DURATION_HOURS` في `data.py`.

## منطق التقاطع (Overlap)
كل مندوب له `start` + مدة حسب نوعه (`DURATION_HOURS`) => `end`.
شيفت المندوب يظهر لمشرف معين لو فيه أي تداخل زمني (ولو ساعة) بين
[start المندوب, end المندوب] و [start شيفت المشرف, end شيفت المشرف]،
مع مراعاة إن الشيفتات ممكن تعدي نص الليل. المنطق موجود في
`data.intervals_overlap()` و `data.get_overlapping_reps()`.

## نقاط مهمة عن سلوك النظام
- **كل تقييم مرتبط بـ (يوم + فرع + مشرف + شيفت المشرف + اسم المندوب)** — لو نفس
  المندوب بيتقاطع مع مشرفين، كل مشرف عنده تقييم منفصل تمامًا لنفس المندوب في نفس اليوم.
- **التقييمات دائمة** — بتتسجل في قاعدة البيانات فورًا مع كل تعديل (مش لما تعمل "حفظ" بس)،
  فلو رجعت لنفس (اليوم/الفرع/المشرف/الشيفت) هتلاقي البيانات موجودة.
- **إنهاء الشيفت** بيقفل التعديل على تقييمات الشيفت ده (يوم/فرع/مشرف/شيفت) نهائيًا
  ويعمل تحميل تلقائي لملف CSV. لو عايز تسمح بإعادة الفتح، احذف الصف المطابق من
  جدول `shift_sessions` في قاعدة البيانات.
